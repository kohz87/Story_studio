Only tier-3 skills have paths. Do this step once for every tier-3 class: it is long, so the class goes in each message.

## The prompt

```
Step 3. Only tier-3 skills have paths. For the tier-3 class {{CLASS_NAME}}, write its branches. For each of its 3 skills:
step 1 has exactly two written branches from the base form (choices "a" and "b"; "g" is generated by the engine - never
write it); then for EACH of the three step-1 forms (a, b and the generated g) exactly two written step-2 branches
(choices "a" and "b"). That is 8 written branches per skill and 24 per class.

Each branch: {"slug","skill","fromForm","step","choice","name","note","transforms":[...]}.
- Form ids: the base form is "<skill>-base"; a step-1 form appends "-a", "-b" or "-g"; a step-2 form appends another
  letter to its parent. So "fromForm" for step 1 is "<skill>-base", for step 2 it is "<skill>-base-a", "<skill>-base-b"
  or "<skill>-base-g". The branch slug must equal the form id it creates (for example "river-cut-base-a",
  "river-cut-base-g-b"). A branch slug never ends in "-g".
- A branch copies its parent form and applies its transforms in order. The ops are set-target, set-element, set-power,
  replace-effect, add-effect, remove-effect, set-cost, set-stat and set-type; "at" is the effect index 0-3, and an op
  that needs "at" must name an effect that exists at that moment. set-element and set-power work on damage, heal and
  shield effects only. A form keeps 1 to 4 effects.
- A written branch must change behavior, not only numbers: change the target, an element, the effect list, the type,
  the stat or the unit. A branch that only sets a different power is refused (numeric-only-branch). The generated "g"
  form is the numbers-only power-up, so the written choices are the ones that differ in kind.
- Budget: a step-1 form <= 60, a step-2 form <= 72 (the parent's score plus your changes). Widening a target to
  "all" or "allies" triples that effect's score, so lower its power in the same branch. Show each branch's score
  outside the JSON (in work/notes.md).
- The two choices should feel like different directions (for example a: wider and weaker, b: focused and elemental). The
  step-2 choices under one parent should differ from each other too.
- Every form that gets a generated child (the base and the three step-1 forms) must survive the power-up: its first
  damage/heal/shield effect at power 980 or less (else stat amounts at 9 or less, else condition rounds at 5 or less).
Output {"branches":[...]} for this one class (24 branches). In a file: add them to content.rules[0].branches of
work/pack.json. I will then name the next tier-3 class.
```

## Check

```
node check.mjs work/pack.json --through 3
```

It should print `OK through step 3`. Typical problems: `branch-graph` (a missing or extra branch, a slug that is not the
form id it creates, `fromForm` naming the wrong parent), `numeric-only-branch`, `budget-closure`, `bad-transform` (an `at`
past the end, or `set-element` on a condition effect). Each tier-3 skill must have all 8 branches before this passes.
